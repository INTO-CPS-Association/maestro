4. Web Interface (API)

The reference below is available without running Maestro. It is generated from the same controller and model annotations used by the live API. Download the OpenAPI JSON document for use with API clients and documentation tools.

On a running server (replace the host and port as needed), interactive Swagger UI is at http://localhost:8082/swagger-ui.html and the machine-readable description is at http://localhost:8082/v3/api-docs. The older /v2/api-docs address is no longer used.

4.1. Session workflow

  1. Call GET /createSession and retain the returned sessionId.

  2. Optionally upload FMUs or other files with POST /upload/{sessionId} using a multipart field named file. Paths in configurations refer to files on the server, not on the client.

  3. Send a multi-model configuration to POST /initialize/{sessionId}. It contains FMU locations, connections, parameters, and algorithm options. The response reports any discovered FMU logging categories.

  4. Send start/end times and logging options to POST /simulate/{sessionId}, or supply a master model to POST /sigverSimulate/{sessionId}. These requests are synchronous and may take the duration of the simulation.

  5. Download GET /result/{sessionId}/plain (CSV) or GET /result/{sessionId}/zip (the session archive).

  6. Call GET /destroy/{sessionId} when results are no longer needed. This removes the session and its files.

For example, after initializing a session, submit simulation times with:

curl -X POST http://localhost:8082/simulate/SESSION_ID \
  -H 'Content-Type: application/json' -H 'Accept: application/json' \
  -d '{"startTime":0,"endTime":10,"logLevels":{},"reportProgress":false,"liveLogInterval":0.1}'

GET /status lists active sessions; GET /status/{sessionId} reports one session. POST /stopsimulation/{sessionId} requests a cooperative stop, not forced process termination. The Scenario operations below generate, verify, visualize, or execute master models without the same session workflow.

4.2. Content types

JSON endpoints, including /status, /status/{sessionId}, and /version, return application/json with structured response schemas in the OpenAPI document at /v3/api-docs. Their JSON body shapes are unchanged; clients should request application/json rather than text/plain.

Send initialization and simulation request bodies as application/json. The /initialize/{sessionId} and /simulate/{sessionId} endpoints also continue to accept JSON encoded as text/plain for legacy clients. The /ping endpoint is plain text, and /result/{sessionId}/plain returns text/csv rather than JSON.

4.3. Errors and execution status

Thrown exceptions normally produce a non-2xx response through the controller exception handler (usually HTTP 500). Some exceptions have different mappings: IllegalArgumentException maps to 404 and UnsupportedOperationException maps to 422. Error responses include diagnostic information and, for internal failures, a log reference. These mappings reflect current behavior and do not imply that every malformed request returns 400.

Simulation exceptions and nonzero CLI exit codes return a non-2xx response and leave the session in Error rather than Simulating or Finished. The elapsed execution time is recorded on both success and failure. CLI stderr is retained for diagnostics, but does not by itself indicate failure: tools may write warnings to stderr while exiting successfully.

Algorithm verification has a separate result contract: inspect correct and errorMessage in the response even when HTTP status is 200. Verification and trace visualization depend on external tools, including UPPAAL verifyta; they are not supplied by the REST API.

4.4. Maintaining the reference

Endpoint descriptions use OpenAPI 3 @Operation annotations and model descriptions use @Schema. Existing Jackson @JsonPropertyDescription annotations are retained for JSON-schema consumers. When changing endpoints or models, regenerate the checked-in reference from the repository root:

mvn -B -ntp -pl maestro-webapi -am \
  -Dtest=OpenApiDocumentationTests,ContentTypeTests \
  -Dsurefire.failIfNoSpecifiedTests=false \
  -Dmaestro.openapi.update=true package

Commit docs/user/api/openapi.json with the source changes. OpenApiDocumentationTests checks the reference against the generated API on subsequent test runs. Sphinx renders that local snapshot, so Read the Docs does not need a running Java server, FMUs, or UPPAAL to build this page.

4.5. Endpoint reference

GET /stopsimulation/{sessionId}

Request simulation stop

Sets the session stop flag. Execution stops when the running algorithm checks it; this is not a forced process termination. Prefer POST; GET is retained for compatibility.

Parameters:

  • sessionId (string, required)

Status Codes:

  • 200 OK – OK

POST /stopsimulation/{sessionId}

Request simulation stop

Sets the session stop flag. Execution stops when the running algorithm checks it; this is not a forced process termination. Prefer POST; GET is retained for compatibility.

Parameters:

  • sessionId (string, required)

Status Codes:

  • 200 OK – OK

POST /visualizeTrace

Visualize a verification trace

Generates an MP4 counterexample trace for a master model. Requires the scenario verifier’s external verification and video tools; fails if a trace cannot be generated.

Status Codes:

  • 200 OK – OK

POST /verifyAlgorithm

Verify a master-model algorithm

Requires UPPAAL verifyta in PATH. Returns a result object, including correct=false and an errorMessage when verification fails or UPPAAL is unavailable; HTTP 200 alone does not mean the algorithm verified.

Response JSON Object:

  • correct (boolean) – True only when verification succeeded.

  • masterModel (string) – Generated UPPAAL XML encoding, or an empty string when unavailable.

  • errorMessage (string) – Verification failure or missing-tool message; empty on success.

Status Codes:

  • 200 OK – OK

POST /upload/{sessionId}

Upload a file to a session

Stores the multipart file in the session working directory for later use.

Parameters:

  • sessionId (string, required)

Request JSON Object:

  • file (string:binary, required) – File to store in the session working directory

Status Codes:

  • 200 OK – OK

POST /simulate/{sessionId}

Run co-simulation

Generates and executes a specification using the session configuration and requested times. The request blocks until execution completes. Execution failures return a non-2xx response and mark the session Error. A nonzero CLI exit code is a failure; stderr alone does not indicate failure.

Parameters:

  • sessionId (string, required)

Request JSON Object:

  • startTime (number:double) – Start time of the co-simulation in simulation time units.

  • endTime (number:double) – End time of the co-simulation in simulation time units.

  • logLevels (object) – Enabled FMI logging categories by instance, using keys such as {FMU}.instanceName.

  • reportProgress (boolean) – Request progress reporting during execution.

  • liveLogInterval (number:double) – Simulation-time interval between WebSocket data updates; zero allows updates at every step.

  • masterModel (string) – Scenario master-model configuration text, used by scenario-based simulation.

Response JSON Object:

  • status (string) – Current session state or operation message.

  • sessionId (string) – Session identifier returned by createSession.

  • lastExecTime (integer:int64) – Duration of the last execution in milliseconds.

  • warnings[] (string)

  • errors[] (string)

Status Codes:

  • 200 OK – OK

POST /sigverSimulate/{sessionId}

Simulate a supplied master model

Executes the supplied scenario master model using the initialized session. The request blocks until execution completes; results are stored in the session directory.

Parameters:

  • sessionId (string, required)

Request JSON Object:

  • startTime (number:double) – Start time of the co-simulation in simulation time units.

  • endTime (number:double) – End time of the co-simulation in simulation time units.

  • logLevels (object) – Enabled FMI logging categories by instance, using keys such as {FMU}.instanceName.

  • reportProgress (boolean) – Request progress reporting during execution.

  • liveLogInterval (number:double) – Simulation-time interval between WebSocket data updates; zero allows updates at every step.

  • masterModel (string) – Master-model configuration text containing the scenario, connections, initialization, and co-simulation steps.

Response JSON Object:

  • status (string) – Current session state or operation message.

  • sessionId (string) – Session identifier returned by createSession.

  • lastExecTime (integer:int64) – Duration of the last execution in milliseconds.

  • warnings[] (string)

  • errors[] (string)

Status Codes:

  • 200 OK – OK

POST /initialize/{sessionId}

Initialize a session

Stores the multi-model configuration and reports available FMU log categories. The specification is generated later when simulation times are supplied. Prefer application/json; text/plain JSON is accepted for legacy clients. parallelSimulation and hasExternalSignals are currently rejected.

Parameters:

  • sessionId (string, required)

Request JSON Object:

  • fmus (object) – Map from FMU identifiers such as {FMU} to FMU file locations on the server.

  • connections (object) – Output-to-input connections. Keys and values use {FMU}.instanceName.signal; each output can feed multiple inputs.

  • parameters (object) – Parameter values keyed by {FMU}.instanceName.signal, with values matching the FMI scalar type.

  • logVariables (object) – Signals to record, mapped from {FMU}.instanceName to signal names.

  • parallelSimulation (boolean) – Request parallel stepping. The web API currently rejects true.

  • stabalizationEnabled (boolean) – Enable stabilization during initialization. The historical JSON spelling is retained.

  • global_absolute_tolerance (number:double) – Global absolute tolerance for initialization and simulation generation.

  • global_relative_tolerance (number:double) – Global relative tolerance for initialization and simulation generation.

  • loggingOn (boolean) – Enable FMI logging.

  • visible (boolean) – Request visible FMU instances during instantiation.

  • simulationProgramDelay (boolean) – Pace simulation steps towards real-time execution.

  • algorithm (object) – Simulation step algorithm. Select fixed-step or var-step using the type property.

  • algorithm.type (string, required)

  • algorithm.size (number:double) – Fixed communication step size in simulation time units.

  • overrideLogLevel (string:enum) – Override the server’s global log level.

  • environmentParameters[] (string)

  • logLevels (object) – Enabled FMI log-category names by {FMU}.instanceName.

  • livestream (object) – Signals to stream over the session WebSocket, mapped from {FMU}.instanceName to signal names.

  • hasExternalSignals (boolean) – External-signal mode. Currently rejected by the initialization endpoint when true.

  • faultInjectConfigurationPath (string) – Path to the fault-injection configuration on the server.

  • faultInjectInstances (object) – Fault-injection instance configuration, keyed by instance name.

  • convergenceAttempts (integer:int32) – Maximum number of convergence attempts used during initialization.

  • externalSpecs[] (string:binary)

  • modelTransfers (object) – Mapping from current instance names to transferred instance names.

  • modelSwaps (object) – Model-swap configuration keyed by the instance being replaced.

Response JSON Object:

  • status (string) – Current session state or operation message.

  • sessionid (string)

  • availableLogLevels (object) – Available FMI logging categories, keyed by FMU identifier. May be incomplete if FMU inspection failed.

  • lastExecTime (integer:int64) – Duration of the last execution in milliseconds.

  • sessionId (string) – Session identifier returned by createSession.

  • warnings[] (string)

  • errors[] (string)

Status Codes:

  • 200 OK – OK

  • multiModel.fmus (object) – Map from FMU identifiers such as {FMU} to FMU file locations on the server.

  • multiModel.connections (object) – Output-to-input connections. Keys and values use {FMU}.instanceName.signal; each output can feed multiple inputs.

  • multiModel.parameters (object) – Parameter values keyed by {FMU}.instanceName.signal, with values matching the FMI scalar type.

  • multiModel.logVariables (object) – Signals to record, mapped from {FMU}.instanceName to signal names.

  • multiModel.parallelSimulation (boolean) – Request parallel stepping. The web API currently rejects true.

  • multiModel.stabalizationEnabled (boolean) – Enable stabilization during initialization. The historical JSON spelling is retained.

  • multiModel.global_absolute_tolerance (number:double) – Global absolute tolerance for initialization and simulation generation.

  • multiModel.global_relative_tolerance (number:double) – Global relative tolerance for initialization and simulation generation.

  • multiModel.loggingOn (boolean) – Enable FMI logging.

  • multiModel.visible (boolean) – Request visible FMU instances during instantiation.

  • multiModel.simulationProgramDelay (boolean) – Pace simulation steps towards real-time execution.

  • multiModel.algorithm (object) – Simulation step algorithm. Select fixed-step or var-step using the type property.

  • multiModel.algorithm.type (string, required)

  • multiModel.algorithm.size (number:double) – Fixed communication step size in simulation time units.

  • multiModel.overrideLogLevel (string:enum) – Override the server’s global log level.

  • multiModel.environmentParameters[] (string)

  • multiModel.logLevels (object) – Enabled FMI log-category names by {FMU}.instanceName.
